# Guided Creator and Participant contract — RC1R12

Core 3.5.0-rc.1.12, SQLite schema 3.2, course schemas 1.0/1.1/2.0. This completes the mandatory engineering scope of the attached 90-section master prompt while retaining RC1R11's focused running-class dashboard and recoverable class/course deletion. Automated release verification is attested in the current validation/seal report; owner Windows/classroom/assistive acceptance remains a separate manual gate.

## One model and renderer

Courses remain declarative `training-engine-course` packages. `module.paths[].steps[].content.blocks` uses the canonical content renderer in the Participant, executable Creator preview and compatible surfaces. Legacy `blocks`, mission practice and empty legacy missions retain their existing behavior. The registry is authoritative: 36 activities, 28 content-block types, canonical result bindings and explicit workflows. Never embed executable HTML/CSS/JavaScript/SQL or credentials. Unsupported guided response models are rejected before import/export/publication. The twelve requested individual embedded question types share ordinary canonical response normalization, scoring, instances and response storage; full team/media/specialized interactions remain the existing dedicated canonical activities, not falsely advertised inline controls.

## Visual authoring

Use Course flow to select a path. Set its title, description, goal, eyebrow, icon, image and choice metadata. Open a step, edit fields and Apply before saving. Steps have stable identities through ordinary edits, duplication, reordering and sharing. Duplicate interactive steps create distinct canonical question identities. Referenced items cannot be removed while dependencies remain. The editor offers all 28 block types with registry-driven scalar controls, repeatable collections, chart data/segments, a real table grid, slides/checkpoints, media and alternative text, formula, prompt mode/helper text and resource cards. No raw data/code editor is needed. Target surface support and property metadata are in CORE_CAPABILITIES.json / the canonical registry.

The ten presets are Instruction, Tool Setup, Prompt Task, Source Review, Choice, Verify, Reflection, Assessment, Evaluation and Completion. Assessment and Choice create canonical embedded questions; Evaluation creates ten individually stored rating/choice/text questions. Variable controls preserve text, numeric and Boolean values. Creator saves are serialized; background autosave updates status without replacing active form fields. A concurrent revision preserves local edits and offers a recovery download before loading the newer Draft. Publication and asset replacement also recheck immutability after awaited request bodies, so a version published meanwhile cannot be changed. Fill the actual instructional content and resources. Presets do not claim to be complete curricula. Content direction can inherit the course or be explicitly LTR/RTL using Core controls. Layout presets are standard, focused, compact, wide, centered, instruction, prompt_task, choice, assessment and reflection; styling remains under Core theme control. Open step inspectors are focused and other steps can stay collapsed.

## Shared steps and variables

Use Variables and shared steps in a path. Milestone and path variables are safe named scalar values. A focused text field can receive a variable through Insert variable; preview resolves values. References are `${name}` with names beginning with a Latin letter and then letters, digits, underscores or hyphens. No expressions run. Missing variables and unsafe/non-scalar definitions fail validation. Builtins: selected_path (stable identifier for backward compatibility), selected_path_title (human title), and path_goal. UI language and authored course language remain independent.

Shared definitions are `module.step_templates[key]`. A use is `{id, use_template, overrides?}`; each use keeps its own analytics/progress identity. Edit shared definition changes every reference; Make independent expands one use while preserving its identity. Definitions never replace completed published versions: edit a Draft/new version. Imported shared overrides are preserved; visual editing of a shared definition does not silently detach it. Delete is blocked while a definition is referenced.

## Branch connections and validation

Open Workflow, select paths/introduction/closing and Create branch connections. This explicit author action replaces only the Draft graph, leaving authored questions/objectives intact; it builds a start, stable-ID participant branches, explicit path conditions, a shared convergence and a closing. It does not guess missing intent on import. The graph distinguishes class/participant connections, conditions, start/terminal nodes and invalid sections. Existing class activity branch rules are preserved and use existing Trainer/flow selection semantics; path rules have a visual selector.

Workflow simulator saves the Draft and enumerates actual canonical graph edges. Every route and terminal is shown; missing destinations, dead ends, duplicate path conditions, unreachable nodes and cycles fail. Limits are 4,096 routes, 512 sections per route and 262,144 traversal operations; exceeding a limit fails closed rather than reporting a partial pass. No unrestricted loop DSL is introduced (the repeat subsystem in master section 23 was conditional, not mandatory). Finite repeated teaching tasks are ordinary explicit stable-ID steps. Repair generated identifiers handles mechanical missing/duplicate step and local block identifiers only. Ambiguous critical references require explicit author repair; no learning objectives, answers or branch intent are automatically rewritten. The branch designer supplies a deliberate convergence scaffold. Export always refreshes manifests and hashes.

Readiness summarizes Structure, Workflow, Assets, Participant runtime, Projector, Accessibility, Languages and Responsive. Actual stored assets are checked for existence and checksum on readiness/export/publication. Required failures block publication/export; Drafts can still be saved for repair. Languages/responsive remain Review in preview instead of falsely certifying an arbitrary new authored course. Validator messages link to affected items and give repair advice. Import repeats critical checks; packages never gain trust merely because Creator exported them.

## Participant behavior

Choice cards accept one path and lock it for that practice. The wizard shows heading/context, progress, instructions, canonical blocks, embedded questions/evidence and sticky actions. Static and editable prompts have a heading, helper text, bounded selectable scrolling, exact-text Copy with accessible feedback/reset, safe Clipboard fallback and saved edits. Resource cards show organization/title/type/description, Open, external indication, Copy link and return guidance, for safe web resources and packaged assets. Unsupported display content has a safe readable fallback, while authoring blocks invalid mandatory definitions.

Required evidence controls Next/Finish on client and server. Types: none, acknowledge, external, text, URL, checklist, file and image. Files/images use existing submissions with exact learner/class/module/path/step/kind ownership checks; guided images require PNG/JPEG/WebP signatures. Uploads need a server connection. Evidence, answers, edited prompts, branch, current step and completed/skipped steps persist. Optional remediation can be skipped honestly; safe path/response equals or less-than conditions can apply to a step or block. Step conditions use earlier saved guided answers; block conditions can also use the current saved question. Unavailable or future response dependencies fail semantic validation, rather than silently disappearing. All question normalization is shared with Creator preview, so numeric equality behaves identically. Preview uses temporary memory and never writes classroom responses/progress.

Trainer-Paced mode retains facilitator control of class scenes and convergence while every learner navigates their own step state. Participant-Paced mode places guided practice alongside nonembedded activities, excludes embedded questions from the ordinary class sequence, prevents leaving unfinished practice and preserves per-unit snapshots when navigating away/back. Front-of-Room mode disables personal controls/writes. No learner advances another learner or the class. A selected personal branch's common review/evaluation/closing uses shared definitions; the explicit class graph converges when the facilitator closes practice, with unused branches truthfully skipped. The M1 browser gate exercises that whole class lifecycle as well as personal completion.

## Connection recovery

Guided prompt/evidence saves and individual answers have a durable device outbox, separate from the existing ordinary response queue. Entries are bound to the signed-in learner; no credentials are stored there. A disconnected answer stays pending and does not falsely enable Finish. Navigation requires server confirmation. Reconnection replays ordered changes; stable request receipts make progress retries idempotent and canonical answers upsert one response. Only the learner's own confirmed write may update the revision of a later unsent local change. Stale-step/revision/class-closed failures remain visible for review, retry or discard; newer device progress is never overwritten automatically. Saved guided changes remain accessible from the account menu even after delivery ends. A server connection is required for fresh page loading, uploads and confirmed advancement; external web tools need their own Internet connectivity. Authored offline guidance is available without promising those external tools work offline.

## Analytics and privacy

Guided reports retain class permission scoping and provide selected path, completion rate/time, current/not-completed step distribution, per-step starts/completions/skips, optional usage, average/median wall time, assessment scores and grouped evaluations. Evaluations retain separate response counts, numeric means, distributions, text responses and completion rate. CSV includes paths, steps and evaluations and protects spreadsheet-leading formulas. Snapshot history preserves completed guided units in Participant-Paced reports. Wall time includes pauses; incomplete durations are excluded, and SQL UTC timestamps are interpreted consistently. Private Trainer cue/explanation/talking_points/expected_answer/common_mistakes/transition fields and unrevealed solutions never appear on Participant/Projector surfaces.
