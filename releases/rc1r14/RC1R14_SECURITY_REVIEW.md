# RC1R14 security and privacy review

Personal settings require authentication and accept only language/theme/accent with enumerated values. Unknown fields, another user ID and malformed values are rejected atomically. Writes update only the authenticated account; partial updates merge after body arrival so independent theme/color writes survive. API/profile/auth responses retain existing permission rules. Editor allowlisting admits only the own-account endpoints. No global settings or public language propagation is added.

Identity is tab-local; local preference values/pending changes are account-namespaced, contain no token and do not overwrite guest defaults. A delayed save acknowledgement cannot erase a newer field choice or clear another account's pending data. Reload merges pending local fields with server fields; authenticated queued saves capture token/account identity. Cross-account storage events do not change another panel. No account is inferred from a shared global preference key.

Finish enforces classroom control rights, confirms intent in the UI, checks optional expected revision and uses one transaction. It closes all still-open activity instances, including suspended break activity, without erasing responses or marking unfinished participant/workflow tasks complete. Duplicate finishes have one audit outcome. Post-body guards reject delayed writes; legacy Projector-control navigation also rejects finished/trashed classes. Existing staff review/report/history/reopen/Trash access remains separate.

Own activity scopes all SQL rows/types/counts to the caller. Staff audit uses existing assigned class/group/admin scope with parenthesized filter logic. Untrusted sizes/page/date/type/search inputs are bounded and parameterized; rows omit private answer/event payloads. Date ranges use inclusive local calendar boundaries converted to UTC and an exclusive next-day end. Deterministic descending IDs and a server-clamped last page avoid duplicated/static truncated pages. Course Editor/Student cannot access staff audit.

All prior authentication/session/default-account, RBAC, audience/reveal, uploads/ZIP/checksum, backup and LAN protections remain under regression. Palette contrast is measured, focus/reduced-motion/RTL are tested; automation does not certify universal accessibility or penetration security. Owner real Windows/LAN/classroom/assistive acceptance remains separate.
