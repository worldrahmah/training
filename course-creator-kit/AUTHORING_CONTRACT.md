# Current authoring contract / عقد التأليف الحالي

Authority order: owner requirements; current RC1R14 canonical registry and verified runtime; descriptive schemas/examples; historical material. A historical prompt cannot add runtime features. Preserve one declarative course model for external import and visual Builder. Supported course schema versions: 1.0, 1.1, 2.0. New explicit workflow work should use 2.0. IDs and accepted version identifiers are stable. Published content cannot be edited in place: fork a Draft/new version and preserve delivered history.

A course JSON document has format `training-engine-course`, schema_version and course. course includes id, version, title, language, direction, objectives and modules. Each milestone/module has its own stable id/title/timing, activities, optional missions/paths and optional explicit workflow. Use templates and schemas, but run the bundled runtime validator: schemas are descriptive, permit compatibility extensions and do not enforce every cross-reference or activity-specific condition. The runtime is the import authority.

The registry defines exact activity, content-block, chart, result, workflow-node, completion and submission identifiers. Do not substitute natural-language labels for IDs. activities/*.json are executable examples, not permission to omit required settings in your own content. ACTIVITY_CATALOG.md explains each response/aggregation/scoring/result binding. Unsupported needs must be documented as **CORE CAPABILITY GAP** with the desired learning outcome, missing behavior, workaround using exact supported components, and owner decision. Never silently approximate an unsupported security, workflow or assessment requirement.

For each milestone supply: measurable objective; observable response/evidence; prerequisites; timing including debrief; Trainer launch/close/reveal/transition flow; clear Participant task and feedback; Projector scene and audience privacy; exact catalog components; supported scoring and result view; private cues; paths/missions where needed; complete workflow if present; licensed local assets; validator output; import-ready files and SHA-256; rehearsal and independent review notes. Keep course language independent from the engine UI language.

Executable JavaScript, HTML, CSS, SQL, event handlers, credentials and custom server code are not course capabilities. Use declarative blocks. Markdown/text are escaped; never require a browser to execute course content. Do not put answer keys in public prose, image alt text, file names, downloadable handouts, asset metadata, captions, objectives or Projector-only prompts before reveal. Upload/file controls do not execute submitted files. Do not ask the owner to paste passwords into AI prompts.

The kit does not certify every generated course. AI authors can create invalid references, weak pedagogy, unsupported branching or privacy mistakes even when syntax passes. Independent review and rehearsal are required.
