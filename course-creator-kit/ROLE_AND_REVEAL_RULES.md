# Role and reveal contract / الأدوار وسياسة الكشف

Trainer: author complete instructions, facilitate, observe cohort participation, moderate where supported, close collection, reveal deliberately, explain, then transition. Private guidance lives only in activity.trainer: cue, explanation, talking_points, expected_answer, common_mistakes, transition. trainer.explanation stays private; activity.explanation is public feedback when reveal permits. Never copy the private object into content blocks or downloadable assets. Authorized Trainer analytics retain stored scoring and ownership; privacy controls do not erase historical evidence.

Participant: supply a self-contained task with the requested response, constraints, time and success criteria. Use the registry's response model, not invented controls. Submission acknowledgements confirm persistence without disclosing correctness or score before reveal. Appropriate post-reveal feedback uses the authored public explanation. Matching offers shuffled right-hand choices without solution associations; sorting does not disclose the correct order; image targets do not disclose solution coordinates. Do not encode solutions in labels or asset names. For paths/missions explain how to choose, begin, submit, seek help and finish. Participant Choice and Practice Gate are orchestration components, not generic response controls; model actual personal work with supported module paths/missions/workflow and rehearse it.

Projector: public prompts and learning scenes, no Trainer notes, identifiable private responses or answer keys before reveal. Use local assets and readable 16:9 scenes, concise text, contrast and large labels. Supported themes are dark, light and high_contrast; course default, class override and live override resolve in that order. A preview in a privileged Trainer browser is a rehearsal, not a security boundary; the actual anonymous paired Projector API is separately tested.

Identity choices vary by activity: inspect exact registry defaults and JSON fields. anonymous/trainer_only/public are not interchangeable and not a universal anonymity guarantee; submissions, audit logs and authorized Trainer reports retain appropriate ownership. Explain the actual behavior to learners. Live result visibility and public explanations follow reveal phases; public handouts cannot enforce a reveal policy.

إرشادات المدرب الخاصة توضع حصريًا في trainer ولا تُنسخ إلى المحتوى العام أو الأصول. شرح trainer.explanation خاص، وشرح activity.explanation عام عند السماح بالكشف. قدّم للمشارك مهمة واضحة وقيودًا وزمنًا ومعيار نجاح، واحفظ الإجابة دون كشف النتيجة مبكرًا. شاشة العرض للجمهور فقط؛ اختبر رابط العرض المقترن الحقيقي ولا تعتمد على معاينة حساب مخول. راجع إعدادات الهوية لكل نشاط؛ إخفاء الاسم عن الجمهور لا يمحو ملكية الإجابة لدى المدرب المخول أو سجل التدقيق. اختبر الانتقال والإغلاق والكشف والنقاش قبل تقديم الصف.

RC1R10 facilitation: the Trainer console supports a continuous pointer and bounded colored handwriting/text annotations, persisted per class until cleared. These are runtime presentation tools, not course JSON fields, executable content, automatic grading or private-cue storage. Do not encode correct answers into public ink before reveal. Staff operations and reports depend on the Admin's granular resource/workspace grants; never assume that a Trainer account has every management permission. Groups and teams are separate, and admission requires registered-account approval.

تدعم أدوات المدرب مؤشرًا متحركًا وكتابة ملونة محفوظة للصف حتى المسح؛ ليست حقولًا جديدة في ملف الدورة أو تقييمًا آليًا أو مكانًا للملاحظات الخاصة. لا تعرض الحل بالكتابة قبل السماح بالكشف. تعتمد إدارة الصف والتقارير على الصلاحيات المسندة. تختلف المجموعات عن الفرق ويتطلب الانضمام حسابًا مسجلًا وموافقة.
