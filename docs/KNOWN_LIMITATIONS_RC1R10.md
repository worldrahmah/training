# RC1R10 known limits / الحدود المعروفة

Owner-acceptance candidate, not FINAL. Inherit RC1R9_SECURITY_REVIEW.md and KNOWN_LIMITATIONS_RC1R9.md: trusted local host/LAN, HTTP without owner TLS termination, no universal vulnerability claim, no MFA/SSO/tenant isolation/malware scanner or tamper-proof audit certification. Exports and local database/storage/backups contain private information and require owner filesystem/transport controls.

New controls are tested with disposable populated state and Chromium automation. Physical Windows devices, classroom LAN conditions, stylus pressure/palm rejection, touch hardware, screen reader usability and owner visual acceptance remain manual/unrun. No OCR, handwriting recognition, pressure-sensitive strokes, object selection/pixel eraser or concurrent multi-author ink merge is advertised. Pen input uses a normalized 16:9 pad mapped to the full Projector stage; it is not a screenshot of the current slide. Choose contrasting ink; clear it when it obscures subsequent scenes. Ink limits: 200 strokes, 500 points/stroke, 20,000 points total, 20 text notes. Pointer is transient and clears after ten seconds without updates; ink persists across slides and restart until explicitly cleared. It is per-class, not embedded into authored course packages or PDF reports.

Attendance is explicit, not automatic presence detection. Each session saves atomically, but saving several sessions is not one cross-session transaction. Unsaved dialog edits disappear if closed. Saved attendance cannot be made unrecorded by choosing a blank option; correct it to the appropriate explicit status. Messages are in-app only, last 100 received messages are shown, and role/group audiences are snapshots at send time. No email, OS push, delivery/read guarantee or scheduled sending. Per-send maximum 5,000 active recipients; retry identity lasts with the stored notification rows. Sending the same intended content in a new composer is a new send. Expiry/deletion of notification history is not a permanent deduplication ledger.

Custom permissions override assignment defaults only when explicitly enabled; absent policies preserve accepted legacy behavior. Wildcard and specific grants combine. Existing administrator privileges are not reduced through resource checkboxes. Course Editor isolation remains authoritative. Menu availability refreshes on reload; server authorizations use current grants. Rollback to old code ignores new restrictions and must be reviewed. Course editing does not imply import permission for ordinary Trainers; import retains Admin/authorized Course Editor policy. User account deactivation affects all classes, unlike withdrawal. The default analytics are summaries of recorded scope; they do not certify learning outcomes or establish attendance.

المرشح غير نهائي. يبقى قبول Windows والشبكة الصفية واللمس الفعلي وقارئ الشاشة والفحص البصري لصاحب النظام مطلوبًا. الكتابة نسبية لشاشة العرض وليست تعرفًا على الخط؛ المؤشر مؤقت والكتابة محفوظة حتى المسح ضمن حدود واضحة. الحضور يدوي والرسائل داخل التطبيق وعضوية المستلمين تُحدد عند الإرسال. قد تعيد النسخ القديمة صلاحيات أوسع لأنها لا تفهم القيود الجديدة؛ راجع التراجع بعناية. حماية ملفات البيانات والنسخ والتصدير واتصال الشبكة مسؤولية تشغيلية لازمة.
