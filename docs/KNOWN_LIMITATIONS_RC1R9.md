# RC1R9 known limits / الحدود المعروفة

Owner-acceptance candidate based on accepted RC1R8. Read RC1R9_SECURITY_REVIEW.md for threat model/residual security findings and RC1R9_UPGRADE_AND_ROLLBACK.md for operational changes. Automated evidence names executed checks; exact archive retest is a separate companion attestation.

1. Owner Windows, real data-path ACLs, physical Projector/LAN, actual branded assets, assistive technology and classroom visual acceptance are pending. Linux/Chromium automation is not all-device acceptance or FINAL status.
2. Local-first HTTP assumes a trusted LAN; no built-in managed TLS/MFA/SSO or general production identity provisioning is introduced. Secure transport/host/backups remain owner tasks. Test accounts require explicit disposable QA mode; never enable it for production.
3. Known historical default-password detection covers documented fixture account names/hashes only, not every weak/reused password. Existing accounts/hashes/data are preserved, with intentional must-change/session gates for unchanged defaults. The operator must protect/delete the private initial password file; Windows ACLs require owner verification.
4. Course resource reads now need an authorized session, eligible enrollment or valid Projector pairing. Previously anonymous arbitrary-version asset URLs are intentionally denied. Legacy unpaired active Projector scenes still show audience-safe state, but their local assets require pairing. Bearer query URLs remain on compatibility download/EventSource paths; protect them.
5. File/media/PDF uploads/downloads are not malware-scanned. Conservative content handling cannot eliminate browser/codec/file-reader vulnerabilities. Shared course assets are available to authorized audiences, so no private cues/credentials/answer keys may be hidden inside them. Do not execute untrusted downloads.
6. The generated kit supports exactly the current declarative registry and validator, not arbitrary HTML/JavaScript/CSS/SQL, custom server code or invented activities/workflows. Descriptive JSON schemas do not replace runtime cross-reference validation. AI-generated courses can still contain pedagogical, privacy or structural errors; independent review/import/publication/rehearsal remains required. CORE CAPABILITY GAP is the escalation path.
7. The all-activity samples are synthetic laboratories, not complete subject curricula. The silent 3-second video/PNG are demonstration assets; replace them with licensed accessible instructional material. External resources are optional and may need Internet/access; classroom delivery must not rely on them. Participant Choice/Practice Gate require actual supported paths/workflow for meaningful independent work.
8. The 68 result-view cases are the defined certification inventory, not every arbitrary combination. Recorded points/participation/attendance/completion are distinct semantics; no external assessment validity or accreditation guarantee is claimed.
9. This release keeps core schema 3.2 and historical migrations. Rollback uses a verified prior app+database+storage backup and can lose later changes; no automatic down-migration is promised. Do not manually edit/reset SQLite. Existing historical archives/guides are evidence, not current authoring authority; current role guides and course-creator-kit supersede them for new use.
10. Security review is targeted and evidence-based, not formal third-party penetration certification, a full vendor supply-chain audit, a tamper-proof external audit service or distributed abuse/DDoS protection. See the detailed review for session, lockout, public metadata and backup caveats.

تظل اختبارات الأجهزة والشبكة والبيانات الفعلية والقبول البصري من صاحب النظام معلقة. التشغيل يفترض شبكة موثوقة أو TLS يديره المالك. لا ضمان لأمان كل ملف أو صحة كل دورة مولدة، ولا دعم لبرمجيات تنفيذية داخل الدورات. الأدلة الحالية وحزمة التأليف الحالية هي مرجع الاستخدام الجديد، وتبقى المواد القديمة تاريخية. التراجع يتطلب نسخة سابقة متحققة مع قرار واضح بشأن التغييرات اللاحقة.

Portable encrypted backup limits: 200 MiB upload and 512 MiB expanded JSON. Larger installations use the existing verified filesystem database+storage backup/restore workflow. Oversized portable export/import is rejected explicitly, without replacing live state.
