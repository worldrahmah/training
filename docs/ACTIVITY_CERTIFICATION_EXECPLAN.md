## Gates
1. Enumerate every canonical activity and every Builder-exposed setting family.
2. Builder: type-specific panel, defaults, apply/save, draft persistence, validation/publish readiness.
3. Runtime: launch, participant interaction or no-input behavior, response validation, scoring/aggregation.
4. Feedback: scored assessments hidden before reveal; after reveal participant gets own correctness/correct answer; Trainer and Projector get correct aggregate assessment context.
5. Surfaces: Admin reporting, Trainer Live, Participant, Projector/result recall.
6. Persistence: restart and backup/restore representative state; all response envelopes remain compatible.
7. EN/AR and responsive/static UI gates.
8. Produce machine-readable and human certification matrix.
9. Run full npm test on source, seal candidate, re-extract exact ZIP, rerun full npm test.

No activity may be marked certified unless its defined flow passes the matrix. "100%" refers to 100% of defined certification gates/settings represented by this matrix, not an impossible guarantee against undiscovered defects.
