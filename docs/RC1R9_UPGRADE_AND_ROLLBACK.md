# RC1R8 → RC1R9 upgrade and rollback / الترقية والتراجع

No database schema change in RC1R9: core schema remains 3.2 and supported course schemas remain 1.0/1.1/2.0. The versioned RC1R8 migrations and populated historical fixtures remain in the distribution. RC1R9 changes labels, branding, authoring material and request/account/file boundaries. Existing users, IDs, password hashes, courses, published versions, classes, enrollment, responses, history, report snapshots and paths are retained. Known default accounts receive existing must_change_password controls and their old sessions are revoked; this is a deliberate security change, not deletion/reset.

1. With RC1R8 running, create and verify a complete database+storage backup. Retain the exact accepted RC1R8 distribution and private backup/credential records securely.
2. Stop the old instance using its supported controls. Confirm it exited; never run two servers on the same SQLite data directory. Keep configured DATA/STORAGE/BACKUP/EXPORT paths.
3. Verify the exact RC1R9 ZIP SHA-256 and internal manifest, then extract to a new application directory. Do not extract over live state. Configure the same persistent paths; do not copy bundled demo state (none is distributed).
4. Start with Node >=22.5 using the normal launcher. Never set TRAINING_ENGINE_TEST_ACCOUNTS in production. Existing populated state is reused; no manual database editing is required. On a truly fresh install, read the operator-only initial administrator file, change the password locally and delete that file securely.
5. Accounts still using historical default passwords must be changed locally before remote sign-in; Admin can reset Participant passwords through supported controls. Existing non-default passwords work normally. Test authorized roles, one existing course/class, a persisted response, report, logo, asset, backup and Projector pairing. Secure and inventory any unchanged historical demo accounts.
6. Retain the verified pre-upgrade backup until owner acceptance. Fresh-extraction automated tests are release evidence, not proof that your LAN/Windows/device paths work.

Rollback: stop RC1R9. The supported safe route is the retained RC1R8 application plus its verified pre-upgrade database+storage backup. Restoring an earlier backup discards changes after that backup; archive newer state before proceeding and obtain the owner's decision on that data impact. No automatic down-migration is claimed. Restored sessions require sign-in. Do not reset SQLite, edit schema checksums, overwrite accepted content or silently discard data to make rollback pass. A random bootstrap file is a local operator secret, not course data; preserve/recover credentials through authorized operator handling, never package it in a release.

لا يغيّر RC1R9 مخطط قاعدة البيانات؛ يحافظ على الأصول والحسابات والمحتوى والتاريخ والمسارات. أنشئ نسخة كاملة متحققة وأوقف الإصدار القديم وافك الحزمة الجديدة في مجلد مستقل واضبط المسارات نفسها. لا تفعّل وضع الاختبار في الإنتاج ولا تنسخ عينات فوق البيانات. غيّر الكلمات الافتراضية محليًا واختبر السجلات والأدوار والعرض والنسخ. للتراجع احتفظ بالإصدار المقبول ونسخته السابقة؛ الاستعادة القديمة تفقد التغييرات اللاحقة ولذلك يلزم قرار صاحب البيانات وحفظ الحالة الحديثة. لا تُصفّر SQLite ولا تعدّلها يدويًا.
