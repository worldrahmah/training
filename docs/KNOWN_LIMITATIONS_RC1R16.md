# RC1R16 operational limits

- Runtime remains local-first. Fresh page loading, server-confirmed navigation and binary uploads need access to the local server. External tools need their own Internet connection. Offline text/evidence/answers are retained and reconciled; an offline error document does not render a fresh class page.
- Old Guided tabs must reload after upgrade. Queued old answers without a revision remain available for review/copy; the server will not guess a revision and overwrite newer confirmed answers. Conflicts require review/discard/retry without silent rebasing of attempted writes.
- The reproduced non-JSON500 failure is proven with exact RC14 fixtures and synthetic response interception. The owner's original deployment/network response was not available; no claim is made about its unseen upstream error.
- Staff messaging is authenticated local direct/group chat with files, voice and two-person WebRTC calls. It is not complete WhatsApp/Telegram feature parity, group conferencing, end-to-end encrypted storage or antivirus scanning. Incoming calls require the staff workspace to be open. Media requires HTTPS/loopback and working ICE; deployment networks can need configured STUN/TURN.
- Performance evidence is an authenticated170-client/five-live-class synthetic HTTP rehearsal, including20attachments and5call-signaling sessions; real two-peer media is tested separately. It excludes170physical browsers/streaming peers and a simultaneous password-hash/login burst. Timing under the cloud's concurrent QA workload is measured, not a universal latency promise.
- Calendar display uses validated local IANA zone/day bounds; recurring dates advance the stored schedule. No cross-DST fixed-wall-clock recurrence guarantee is implied.
- No software audit certifies100%security against every known/future attack. Actual authorization/privacy/input/upload/CSRF/idempotency/migration/integrity/reconnect checks are reported with limits.
- Owner Windows/LAN deployment, actual microphones/cameras, classroom visual and assistive acceptance are unrun cloud-external gates. Environment draft save is separate from user publication/fresh-task restoration. Project status remains OWNER_ACCEPTANCE_CANDIDATE_NOT_FINAL until owner acceptance.
