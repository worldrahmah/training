## Authorized deliverables

One coherent owner-acceptance candidate: shared system logo including sign-in and replacement instructions; capitalized English and fully Arabic activity labels without changing IDs/authored text; complete EN/AR Admin, Trainer and Student guides; current AI Course Creator kit including guided intake, all supported activities, schemas, examples, role-specific authoring, private Trainer cues, workflows, scoring/reveal, assets, validator/packager, importable samples, starting and independent final-review prompts; meaningful security audit/repairs; no visible demo credentials, separate test accounts and safe production account handling without losing users/data.

## Architecture and data

Evolve the existing local-first Windows/LAN application. Keep one canonical declarative course model and capability/activity registry, stable IDs, all 36 activities and 68 result-view cases. Course packages must not execute JavaScript, HTML, CSS, SQL, credentials or server code. Explicit workflows need complete valid references, transitions, branches, reachability, terminals and deterministic Trainer completion. Preserve users, versions, classes, enrollment, responses, history, reports, assets and backups. Before schema changes document impact; use versioned deterministic migrations, test populated historical databases and never reset SQLite or require manual database edits.

## Roles and privacy

Server-enforced fail-closed permissions; preserve Course Editor isolation. Class codes admit registered accounts only; requests remain pending until an assigned managing Trainer approves, with Admin intervention permitted. Trainer cues stay private. Participant tasks must be clear, Projector content audience-safe and answers withheld until reveal permits them. Writes report actual outcomes, are auditable and handle retries honestly.

## Design and language

Preserve accepted typography and font choices. Verify responsive professional accessible EN/LTR and complete AR/RTL, punctuation, mixed content, charts/tables and labels; light/dark, contrast, focus, keyboard, touch targets, menus, dialogs and scroll/narrow screens. UI language remains independent of course language. Never expose raw IDs/JSON/debug terms in normal UI or change canonical identifiers for appearance.

## Course Creator

Advertise verified capabilities only; report unsupported requirements as CORE CAPABILITY GAP. Guide intake, then author one milestone/module at a time unless the owner explicitly broadens scope. Freeze accepted IDs. Include objectives/evidence/timing, Trainer flow, Participant paths, Projector scenes, exact catalog components, executable workflow where needed, assets, validation, import-ready files, SHA-256 and independent review. Test examples via actual import/publication paths. Do not promise error-free AI courses.

## Security and evidence

Document the threat model and meaningful protections with honest limits; no universal security claim. Preserve signature/checksum/TLS verification. Never print credentials/tokens/private environment values. Reuse supported existing authentication. Run unchanged baseline before major changes, add regression tests for repairs and verify role/data semantics, API/database/migration/browser/EN-AR/responsive/accessibility/scoring/reveal/restart/reconnect/backup and certification behavior as applicable. Distinguish passed, failed, skipped and unrun results; do not hide failures.

## Reliable continuation

Reuse the published environment and existing checkout; no additional worktree unless requested. Verify tools/workspace/branch. Save tested reusable setup/start/readiness instructions. Processes do not survive snapshots. Distinguish provisioning/authentication failures from defects; saved configuration/publication does not establish new-task readiness. Commit meaningful completed work and maintain continuation notes/evidence so environment loss does not erase progress.

## Delivery and working style

Proceed autonomously, preserve completed work, repair failed gates and give concise candid updates. Ask only unresolved material architecture/data/permission/product questions. Complete full working-tree checks, generate manifest/checksums, seal immutable ZIP, freshly extract exact bytes, verify CRC/safe unique paths and checksums, rerun complete required suite from extraction and supply seal report/evidence/limitations/upgrade/rollback/owner checklist. Deliver complete GitHub downloadable package and exact SHA-256 including source/runtime/migrations/guides/current kit. Remain an OWNER_ACCEPTANCE_CANDIDATE_NOT_FINAL until owner real-browser/classroom/Windows visual acceptance; automation alone is not FINAL.
