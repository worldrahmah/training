# ONE design standard — professional classroom ambition

The owner's ambition is a teaching platform that feels ahead of its time in every detail. This is a quality objective, not an external world-ranking claim. Exceptional design is demonstrated by classroom usefulness, coherent interaction, accessible typography, truthful state and reliable recovery.

## Governing principles
- The current task is immediately clear. Essential actions have one strong visual priority; secondary controls are grouped without burying recovery.
- Admin governs; Trainer prepares and manages authorized work; Live facilitates; Participant learns; Projector presents; Builder authors. Each surface has its own information density and operational priorities.
- Use generous but purposeful spacing, restrained color, semantic states and precise typography. Decorative effects must not reduce clarity or responsiveness.
- Montserrat and Cairo are actual locally loaded assets, not nominal font-family declarations. Arabic mirrors navigation/control flow while course language/direction stays independent.
- Every mutation has truthful pending, success, validation, failure and retry behavior. A saved indicator comes from persisted state. A closed activity never claims an unsubmitted response was saved.
- Data visualizations communicate meaning. Show complete returned data and visible filtering; forbid invalid averages/proportions or categorical trends; provide readable labels, zero/negative handling and a table equivalent.
- Keyboard focus is visible, contained in dialogs and returned when they close. Dialogs have names and proper semantics. Reduced motion and forced-color support are first-class.
- Private facilitation belongs to the Trainer. Audience design is backed by server-safe payloads; visual hiding is insufficient.

## Remaining platform design program
Before a whole-platform design claim, audit every principal screen, dialog and state using a page/component ledger. Consolidate remaining legacy CSS/helper patterns, reduce Live toolbar density, improve activity-specific Builder/Participant previews and accessible media/drawing controls, strengthen help and first-run guidance, test long translations/populated tables and all activities across roles/themes, and perform owner room-scale visual acceptance. Evolve the shared design system while preserving proven delivery behavior.

School design must follow approved audience/privacy scope and capability profiles. A complete school workflow is not created by renaming Trainer to Teacher.
