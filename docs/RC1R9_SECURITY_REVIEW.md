# RC1R9 security review and threat model

Owner-acceptance candidate; targeted source review and executable regression, not a formal penetration test or a guarantee against every vulnerability. Findings below distinguish repaired behavior, existing protections demonstrated by tests and residual limits. Current evidence is under docs/verification/rc1r9; exact sealed-byte retest is attested in the companion seal report.

## Trust model and scope

Protect users/password hashes, sessions, private profiles/submissions, Trainer cues, pre-reveal solutions/scores, immutable course versions, class scope, staff grants, backups and persistent files. Treat unauthenticated LAN clients, signed-in Participants, unassigned staff, restricted Course Editors and malicious/malformed course/uploads as untrusted. Authorized administrators and the installation OS operator remain privileged; compromise of either can compromise local data. The application is local-first on a trusted classroom LAN. Network interception, a compromised host/browser, malicious privileged operators and secure enterprise identity provisioning require controls beyond this candidate.

Reviewed boundaries: core UI escaping/links/session handling and every entry surface; server token/role/class/course guards and upload/download/import/publish routes; workspace admission/groups/profile/archive permissions; report snapshot/download authorization; ZIP parser/course validator; password storage/default bootstrap; backup crypto/verification and restore journal. Existing executable suites supply additional regression coverage. Route inventories alone are not proof every handler/parameter has undergone a penetration test.

## Existing protections verified by retained suites

Password hashes use salted scrypt and timing-safe comparisons. Idle expiry, device session limits, temporary-password gates, self password changes and session revocation are exercised. Staff elevation/deactivation is checked for authorization, partial-write prevention and last-active-super-admin protection. Course Editor routes remain isolated; view/edit/publish grants are distinct. Registered-account class-code admission remains pending, checks capacity/revisions/assignment and cannot use a guest route. Archive/re-add preserves historical evidence. Profiles/photos are own/authorized-staff only; reports recheck current scope on download and preserve reviewed data. Private Trainer fields and solution mappings are projected out of audience content; stored scores remain available to authorized staff while pre-reveal acknowledgements do not disclose them. Course imports remain declarative, validate cross-references/explicit workflow and use bounded CRC/path/duplicate/checksum ZIP checks. Published content is immutable.

Backups require administrator access, verify hashes/database integrity and include storage. Portable backups use scrypt-derived AES-256-GCM with random salt/IV and authentication tag. Restore has a filesystem journal, safety backup, deterministic recovery/rollback and session revocation; failed recovery remains fail-closed. Populated historical migration tests retain users/hashes/responses/assets and check versioned migration checksums. Local shutdown requires the instance nonce and loopback peer, preserving unrelated processes. Professional PDF tests exercise role restrictions, snapshots, real logo/photo, backup restore and seven templates in EN/AR/all accepted fonts.

## Residual limits and deployment requirements

- LAN HTTP is plaintext. Use a trusted classroom network and owner-managed TLS termination for hostile/shared networks. The application does not install certificates or claim transport confidentiality. A reverse proxy must preserve same-origin Host/Origin and protect its own headers; resource cookies add Secure only for a directly encrypted connection.
- Sessions remain bearer credentials in sessionStorage for JavaScript APIs, and legacy EventSource/download paths may use query tokens. CSP/escaping/referrer policy reduce risks but do not eliminate XSS, browser compromise, URL history, proxy-log or extension exposure. Do not share such URLs. Resource cookies are read-only asset credentials, not an identity/session redesign.
- A local OS administrator can read SQLite/storage and change code. File mode 0600 is verified on Linux; the Windows operator must restrict folder ACLs. Account default remediation detects the documented historical TRAINER and DEMO01–08 hashes, not every weak/reused owner password. Strong owner passwords and least privilege remain necessary. No MFA/SSO/password recovery service, hardware key integration or formal identity assurance is claimed.
- QA fixture mode intentionally enables known passwords/sample data. Never set it for production or snapshot QA state as institution data. Tests use separate temporary paths; the release contains no live database, storage, credentials or session tokens. Bootstrap files are local operator secrets and must be deleted after use.
- Same-IP throttling is process-local and can affect many legitimate users behind one address; it is not distributed DDoS protection. Account lockout can be abused to deny a known username temporarily. Reverse-proxy abuse protection and operational monitoring remain owner responsibilities.
- Files are not antivirus-scanned or certified safe. PDF/media/browser codecs have independent attack surfaces; keep browsers/OS current and never run untrusted downloads. Authenticated course assets are learning resources available to authorized course audiences; do not store private cues, secrets or answer keys in shared assets. Legacy unpaired Projector content may show the current audience-safe live state, but local course assets now require pairing/session.
- Public health/settings expose limited application/network/branding metadata. Certificate verification is bearer-code access to the certificate's intended public fields. Public refresh events contain operational refresh metadata; they are not a private notification feed. Do not deploy this classroom host as an unreviewed public Internet service.
- Portable encrypted transfers retain the 200 MiB upload limit and now have a 512 MiB expanded JSON bound. Larger state must use verified filesystem database+storage backups; failed oversized imports never reset active state.
- Audit records are local, not append-only externally attested forensic logs. Encrypted backup confidentiality depends on the passphrase; unencrypted backups/exports require access control. The review is not a formal supply-chain audit of every bundled PDF/font/browser dependency or a third-party penetration certification.
- Manual Windows/real LAN/actual Projector/owner logo/assistive technology/classroom acceptance remains pending. Automated browser checks cover the named matrix, not every browser/OS, every possible hostile payload or every pedagogical use.
