Status remains OWNER_ACCEPTANCE_CANDIDATE_NOT_FINAL until owner signs off. Use a verified backup and disposable classroom before production. Record device/browser/OS, language/theme, result, screenshots and unresolved defects.

- [ ] Registered student requests a class by code; pending request not enrolled; managing Trainer bell/admissions review, approve/decline, capacity/prerequisites and private data remain correct.

- [ ] Admin customizes view-only, edit, publish, archive, classroom control, enrollment, teams, attendance, messaging and participant-account rights. Test denied writes directly and through UI, reload menus, verify Course Editor isolation and Admin rights.

- [ ] On actual touch/mouse/stylus hardware, move pointer smoothly and write colored/varied-width strokes; undo/clear; reconnect/restart; inspect paired 16:9 Projector, light/dark scenes and contrast. Verify ink doesn't cover the next scene accidentally.
- [ ] Analytics shows accurate authorized cards/charts before existing PDF/Chart builder/details. Scroll every section on phone/tablet/desktop EN/AR, inspect default chart tables, choose CSV dataset/class and reviewed PDF template/language/date; inspect actual exports.
- [ ] Complete EN/AR RTL, mixed-direction text, keyboard/focus/dialog/menu/scroll/touch/contrast and screen-reader acceptance; preserve typography and authored course language.
- [ ] Rehearse all 36 activity types and relevant 68 result cases/reveal/scoring/private Trainer cues, code admission, offline queue/reconnect and backup/restore on Windows/classroom LAN.
- [ ] Read six guides, current Course Creator kit, security boundaries and known limits; sign owner acceptance or list remaining defects. Automation alone does not make this FINAL.
