# RC1R10 security changes and verification boundary

Threat model: authenticated Students or lower-privilege Trainers attempt unauthorized writes, private messaging/receipt access or permission bypass via legacy APIs; malformed attendance/team/ink requests corrupt history or consume unbounded resources; retries duplicate notifications. Trusted host/database administrators remain outside the application's isolation boundary. Inherit the RC1R9 request/file/authentication threat model and tested protections.

Repairs: server-side custom restrictions before legacy route dispatch; shared effective class permission resolver; separate enrollment/profile-edit/account-deactivation grants; group bulk plans reauthorize required class actions at preview/apply; messages resolve eligible active scoped recipients server-side and reject unauthorized audiences before any writes; transactional fanout/deduplication and send-request payload hash; read receipt visibility checks; atomic membership moves, historical team response deletion guards; strict atomic attendance validation without a present fallback; pen palette/coordinates/count/point/width bounds; transient pointer updates with authentication/control checks, backpressure and expiry; authorized no-store photo blobs without session tokens in avatar URLs. Account deactivation revokes sessions. No executable course content or schema expansion.

Evidence gates: tests/rc1r10-experience.mjs positive and negative state assertions; tests/browser-rc1r10.py real UI plus mouse/touch paired Projector; complete existing Node/browser/PDF/legacy-migration/restart/backup/36-activity/68-result suites. See committed verification results for actual passed counts; no source inventory alone is a PASS. Initial concurrent full run encountered a Projector-presence startup timeout; isolated rerun passed. Full serial final gate is required before sealing. An earlier pointer source-inventory assertion was updated to inspect its new shared module. Browser CSP remains unchanged; browser predicates use functions rather than unsafe string evaluation.

Limits: no universal penetration-test claim; no security guarantees for hostile host administrators, broad Admin grants, raw LAN interception, external documents/media or an owner-reverted old runtime ignoring new policies. Physical device and owner classroom acceptance remain unrun. See KNOWN_LIMITATIONS_RC1R10.md and RC1R10_UPGRADE_AND_ROLLBACK.md.

LAN compatibility check: message request identities use getRandomValues rather than secure-context-only randomUUID. The repair browser suite explicitly removes randomUUID to exercise the capability available on ordinary classroom HTTP origins; this does not certify physical LAN latency or transport secrecy.

Delayed-body regressions verify recipient resolution after membership changes and protect team response history when a response arrives before automatic regrouping commits. Enrollment delegates receive admission notifications even when their assignment is not Lead. Unlisted historical resource grants survive permission-dialog saves.
