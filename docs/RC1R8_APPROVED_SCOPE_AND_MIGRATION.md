# RC1R8 approved product and migration contract

Owner decisions, 14 October 2026: Course Editors author their own/assigned courses and may publish assigned courses; persistent named participant/staff groups allow multiple membership; assigned trainers with management rights approve admission and Admin may intervene; re-enrollment resumes existing progress; seven branded PDF reports; central company branding; private role-authorized full profiles; one organization per local installation. Bulk-operation previews, approval inbox, audit/history and archive/restore are included. New code admissions require registered accounts (owner's follow-up answer). No school-domain or tenancy expansion is authorized here.

Reported repairs: withdrawn participants must leave the current roster and return to the add picker, without deleting responses/history; milestones must support reviewed deletion; blockers identify affected content, cause and actionable repair; metric summaries open searchable authorized records; sidebar stays stationary while page content scrolls; backup controls wrap without overflow.

Typography: at least 20 English and 20 Arabic families, locally bundled with licenses/provenance, centrally selected by Admin and applied across management, learner, authoring and Projector. Montserrat/Cairo remain the initial defaults; no remote font service is required. Validate text shaping, responsive layouts and exported PDF readability rather than promising that arbitrary metrics are inherently safe.

Migration impact (before implementation): retain legacy migration compatibility, then run transactionally journaled extension migrations. Widen staff_roles CHECK to include course_editor while copying all existing roles/timestamps unchanged. Add group/membership and join-request tables with foreign keys, indexes, owner/audit metadata, and explicit pending/approved/rejected transitions. Add profile-media references and versioned setting metadata as needed. Never delete old enrollments/responses, rewrite published content, or infer progress resets. Existing active learners remain active; new admissions await approval. Rejected writes and failed migrations make no partial accepted changes.

Upgrade: checkpoint and verified backup of database plus storage before applying schema changes; retain the previous application and pre-upgrade backup. Additive tables permit record preservation, but an older release does not understand new editor roles or approval semantics. Rollback uses the verified pre-upgrade backup if new features have been used; never edit the database manually or silently discard new records. Test repeat startup, populated v2.1.1 and RC1R7 upgrades, denied access and backup/restore of the new state.

Report contract: Class, Learner, Course, Attendance, Assessment, Participant Group, Trainer Activity. Use actual recorded evidence, privacy/reveal policies, authorized scope and clear absent-data states. Central company logo/contact/footer, date range, EN/AR, readable multi-page tables/charts, direct downloadable PDF. No fabricated percentages or unrelated learner/organization data.

Report migration impact, recorded before implementation: extension 0004 adds immutable professional report snapshots (owner, template/resource, reviewed data, expiry and exported-file checksum), without modifying legacy report snapshots. Exported PDFs and uploaded branding live inside backed-up storage. Download rechecks the owner's current resource/class permissions; revoked access denies old exports. Draft previews expire after one hour; accepted exports persist. The reviewed report captures branding and font selection so export cannot silently change after preview. Existing reports and exports remain available.

Release gates: complete Node and browser regression, all 36 activities/68 result cases, new stateful authorization/admission/group/report/migration tests, meaningful EN/AR font/layout/PDF checks, working-tree verification, clean immutable ZIP, fresh extraction, CRC/path/duplicate/all-current-checksum verification, complete tests again, seal report and exact SHA-256. Publish an owner-acceptance candidate on the testing branch; Windows/projector/manual acceptance remains required for FINAL.
