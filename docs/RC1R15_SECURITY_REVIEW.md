# RC1R15 security review

Threats reviewed: unauthenticated/cross-origin writes, participant entry to staff tools, Course Editor classroom bypass, conversation/task/note IDOR, administrator privacy overreach, removed group members, revoked granular grants, delayed request bodies, duplicate sends, attachment traversal/type/size/quota/integrity, stored XSS, private audit payload leakage, call impersonation/oversized signaling, stale task/note writes and bounded query/request workloads. Existing authentication/session expiry/rotation, course package execution prohibition, backup/import/ZIP traversal/bomb/reveal tests remain mandatory. SQL uses bound values; dynamic identifiers/operators come from fixed internal allowlists. Notes and chat render escaped text. Attachments require live authenticated membership and download with attachment disposition plus sandbox CSP, never a public static path. Voice playback uses authenticated fetched blobs. Files have size/quota/type/signature bounds and SHA integrity. New writes recheck staff identity/permissions/membership after body arrival. Resource counts/pages/signals and send/upload/call rates are bounded.

Chat is stored locally and is not end-to-end encrypted at rest. Host administrators/backups can contain private content; use disk encryption and encrypted backup/export controls. Downloaded Office/PDF/audio files are not an antivirus guarantee. Deploy malware scanning and endpoint protection where required. This review is not a penetration-test certification, exhaustive testing of all attacks, or a 100% security guarantee. Browser/OS/runtime updates, production HTTPS/certificate/proxy configuration, relay credential governance and real network/hardware acceptance remain operator responsibilities. No claim of 170 real simultaneous media streams follows from the HTTP workload.

New test receipts record actual counts and outcomes; do not infer a PASS from this narrative. Run node tests/staff-collaboration.mjs, node tests/staff-load.mjs and python tests/browser-staff-collaboration.py plus all inherited checks. The managed cloud Chromium disables non-proxied UDP; the media browser rehearsal uses an authenticated loopback TURN-over-TCP relay without changing browser security policy. Relay binaries are a development-test prerequisite only, obtained via signature/checksum-verifying Debian APT, never part of the classroom runtime or a required cloud service.
