# RC1R12 security/data boundary review

Retains the existing authentication, RBAC, admission, private Trainer/audience projections, safe Markdown, package/asset paths, ZIP integrity and backup protections. New guided code accepts declarative data only. Registry property forms add no HTML/CSS/JS execution path. Server verifies current learner/class/module/path/step, selected branch, required evidence, optimistic revision and canonical response type. File/image evidence checks exact submission ownership and image signatures; existing authenticated file download restrictions apply. Export/readiness/publication verify stored asset integrity, and import independently validates packages.

Progress retry receipts bind an exact request body to a learner's saved runtime; altered retry bodies fail. Outbox rows carry learner identity and no credentials; transport captures the matching session, and stale conflicts are retained. Only unsent local changes following that learner's own confirmed write may follow its revised revision. No cross-account replay or silent overwrite of a newer device. CSV values protect spreadsheet-leading formula characters. Reports remain within existing class visibility rules; private cues/solutions stay off audience surfaces.

This is an engineering review and automated regression evidence, not formal penetration certification. Existing local LAN HTTP transport assumptions remain; use the owner's trusted LAN or TLS termination. No new cloud service, tenant boundary or unrestricted executable/repetition engine is introduced. No data reset or migration was needed.
