## Runtime and Creator

The same `guided.js` renderer and binder power Participant practice and Builder's Participant preview. `renderer.js` remains the single content-block renderer. Canonical `step.content.blocks` now renders; legacy `step.blocks`, body, prompt and resources remain supported. Shared prompt cards copy only the current prompt text, show localized live feedback, wrap/select/scroll long text, and offer editable prompts with reset and saved progress. Resources pass through the existing safe URL/local-asset renderer. No course-specific tool logic, HTML, CSS or executable expressions are accepted.

Running classes take priority on the Participant dashboard: hero, then the current class task. Learning, tools, learning record and recent activity appear in four native closed disclosures underneath. The arrows work with keyboard/touch in either direction; open state survives background updates within that page/class. A reload starts them closed. Other dashboard data still refreshes. The live guided task and input selection survive unrelated background updates. Outside a running class, existing sections remain directly available.

Builder preview runs a temporary selected path, evidence, edits and responses without writes to production progress. Restart preview tests the other branch. Desktop/tablet/phone widths and explicit course LTR/RTL are independent of UI language. The Tools menu now exports validated course ZIPs after saving the draft. Export includes verified local assets and a SHA-256 manifest, is limited to authorized course editors/Admins, and fails closed for incomplete structure/workflow/assets or a changed asset checksum. The exported version is explicit; published source content is never modified. A test imports the actual exported ZIP into a second isolated server and runs its Participant path.

The guided editor supports step templates, title/body/completion, optionality, duplicate/reorder/delete, canonical blocks, prompt helper text and existing module question references. Existing workflow editing, structural/asset/publish validation and simulation remain in place; no second course format.

## Declarative contract

Use `path.guided:true` for the checked RC1R11 navigation contract. New embedded interactions also require checked navigation. Explicit stable step IDs are required for these new definitions; generated Creator IDs use UUIDs and ordinary editing retains them. Legacy paths keep their existing import/API compatibility, with warnings for old duplicated step IDs.

- `step.interaction:{activity_id}` or `step.interactions:[{activity_id},...]` references ordinary activities in the same module. Each referenced question appears within the step and saves separately. Supported individual types: single_choice, multiple_choice, rating, confidence, reaction, short_answer, long_answer, numeric_answer, checklist, reflection, self_assessment, true_false. Team and advanced media/submission interactions are rejected here; use their existing full activity surfaces.
- Responses use ordinary `activity_instances` and `responses`, canonical normalization and server scoring. They appear in existing authorized reports. Guided instance metadata distinguishes path/step and prevents bypass through the ordinary live response endpoint. A retry updates the same response instead of duplicating it. No pre-reveal score or private trainer fields are returned to learners.
- `completion.type`: none, acknowledge, external, text, url, checklist. Checklist evidence declares `completion.items`. Embedded responses and evidence gate forward navigation on the server. Optional steps may be skipped. Previous does not erase evidence. New guided file/image evidence is rejected rather than silently accepted; use existing submission activities outside the wizard.
- `when:{path_id}` or `when:{activity_id,equals:literal}` / `when:{activity_id,lt:number}` provides safe step/block visibility from the selected route and saved canonical responses. No scripts or expressions. Support content is skipped without pretending it was requested. Author conditions should reference earlier questions.
- `module.variables` and `path.variables` supply plain scalar display context. `${selected_path}` and `${path_goal}` are built in. Missing referenced variables fail validation. Resolved text is escaped by the existing renderer. IDs and canonical references should remain literal stable IDs.
- `module.step_templates:{name:{...step fields}}` can be reused through `step:{id,use_template:'name',overrides:{...}}`. Each use keeps its own stable response/evidence identity; template updates flow through normalization and preview. Do not use executable template content. No unrestricted/bounded loop subsystem is introduced.

Progress stays in the existing SQLite runtime JSON: evidence, edited prompts, entered/completed timestamps and canonical response references. Navigation derives the next position on the server, locks the selected path, rejects missing references/forged modules/step jumps/incomplete finish, and checks expected revision. Completion awards existing path objectives/achievements. Practice closure and class-wide convergence remain under existing Trainer control; individual navigation never advances another participant or the whole class.

## Reporting and deletion

The new Guided learning report is available in authorized Admin/Trainer Reports, with separate question distributions, numeric averages, text responses and CSV export. The scoped API also exposes per-path completion/current/drop-off positions and per-step mean/median elapsed time. Timing is wall time including pauses, not measured attention. CSV cells are escaped against spreadsheet formula execution. Existing permission scope and reports remain authoritative.

Delete course/class is now directly visible in authorized collection actions and requires confirmation explaining preservation and restore. Deletion moves records to the existing archive. It preserves course versions, classes, enrollments, answers, assets and reports; Archive & restore reverses it. Active classes must finish before deletion. Repeated deletes are idempotent and retain the pre-archive status. There is no permanent purge of delivered history.

## Upgrade, rollback and limitations

No SQLite schema/table migration is required; core schema remains 3.2. Existing 1.0/1.1/2.0 packages and immutable published versions remain supported. Back up database and storage with the existing verified backup flow before upgrading; stop the server, replace only application bytes, and retain all configured data/storage/backup/export directories. RC1R10 cannot deliver newly introduced RC1R11 guided definitions correctly; use retained immutable RC1R10 course versions for a rollback rehearsal. Roll back application bytes to the verified RC1R10 artifact; do not overwrite newly collected data with an older backup without review.

See the gap matrix for advanced limitations. In particular: guided writes currently require a connection to the local server; ordinary activity offline queues remain unchanged. File/image/team/advanced-media embedded questions are intentionally rejected. Shared template/variable/block-condition definitions are externally declarative; the visual inspector does not yet provide every advanced authoring operation. These limits must remain visible in the capability contract and handoff. Do not treat this as completion of every aspirational Creator feature in the attached master prompt.
