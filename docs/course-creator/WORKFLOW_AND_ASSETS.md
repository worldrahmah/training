# Workflow and assets / المسارات والأصول

If a milestone has no explicit workflow, the supported legacy linear sequence applies. If you add workflow, supply start_node_id, a nonempty nodes array and edges. Nodes have stable id, an exact registry workflow type, and valid activity_id, mission_id or path_id where required. References must resolve inside that milestone. Every required node is reachable from start; ends must be explicitly terminal; conditional branches must have valid destinations, scope and supported condition objects. Do not invent a transition because a node lacks an edge. Model personal branches with participant-scope edges and convergence back into the class flow as the runtime supports. Validate ambiguous, cyclic/unreachable and missing-terminal cases with the executable validator and simulate in Builder. Rehearse Trainer completion, personal completion and reconvergence. The workflow-paths sample is a concrete supported example; it is not a universal branching engine.

Build one milestone and prove its paths before adding another. Preserve accepted node/activity/path IDs when revising wording. Do not publish if a learner can become stranded or the Trainer cannot deterministically finish the milestone. Timing is authored intent, not an automatic progress guarantee. Minimum-response/completion gates must match the actual class and intended evidence.

Use a course directory containing course.json and assets/. Only package supported local file formats. Prefer PNG/JPEG/WebP and supported MP4/WebM/audio; verify codec support on owner devices. Samples include a locally generated 3-second silent H.264 video and a fixture PNG; no network or media service is needed. For your course provide rights/license records, transcripts/captions/alternatives, dimensions/duration, file size and SHA-256. Never bundle executables or credentials. Resolve every asset://assets/... or assets/... reference. External links can be optional resources; they cannot be required for offline classroom delivery. Do not assume imported PDF/PPTX preserves all presentation features; inspect generated declarative blocks and local resources on all role surfaces.

`node tools/package-course.mjs course-directory output.course.zip` reads only regular local files, rejects symlinks, validates actual ZIP bytes and writes manifest.json with per-file SHA-256 plus a companion ZIP hash. Keep the output outside the source directory. Existing outputs are refused; use a new version. An archive has no self-hash inside itself: the external companion attests its final bytes. Do not edit a sealed ZIP. Verify with the validator and compare the SHA-256 after transfer. Package path/CRC/duplicate/expanded-size checks remain enabled.
