# RC1R15 upgrade and rollback

Stop the old server. Make and verify a full backup of the existing database, storage and configuration. Extract this release to a new application folder and retain configured DATA/STORAGE/BACKUP/EXPORT paths. Start normally without TRAINING_ENGINE_TEST_ACCOUNTS. Never replace owner data with QA fixtures. Workspace migration 0007 runs once after the existing automatic checksummed pre-upgrade database/storage backup; accepted migration checksums are immutable. Fresh and populated historical fixtures are tested. Collaboration files reside in storage/staff-chat and are included in ordinary full/encrypted backups. Verify users, classes, rosters, history, messages/files/tasks/notes and report access after restart.

Finish a live class before moving it to Trash. Restore retains history. Permanent class deletion removes personal notes with other class records; export first. To roll back, stop the server and restore the matched pre-upgrade database/storage/application/configuration backup together. Do not downgrade a migrated live database in place. Changes made after that backup require deliberate export/migration; rollback cannot preserve them automatically.

For LAN microphone/camera access, terminate HTTPS using a trusted local certificate and a reverse proxy that preserves same-origin requests. HTTP LAN classroom/chat/text/files work, but browsers restrict microphone/camera. Configure optional STUN/TURN under Staff workspace → account menu → Messaging settings. Do not expose this local application publicly without deployment review, HTTPS, trusted proxy policy, backups and host/network hardening. Administrator-managed TURN credentials are delivered to authorized staff browsers to establish calls, as required by WebRTC; use limited relay credentials and rotate them. No external relay is required on a directly reachable network.
